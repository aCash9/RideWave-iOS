RideWave · SwiftUI code tour

A small riding companion with a surprisingly careful core.

This guide explains how the iOS project moves from onboarding to ride mode, how Spotify and contacts stay isolated, and where tests protect the risky edges.

The mental model

The app is a SwiftUI shell around three stateful domains. RideWaveModel decides which screen exists; SpotifyController owns authorization, App Remote, playback commands, and lifecycle; contacts and playlists appear as isolated fullscreen overlays.

SCREEN STATE

ContentView

Chooses tutorial, connect, or ride. It owns scene-phase changes, callback URLs, screen-awake behavior, and the transition into ride mode.

What host tests cannot prove

Mocked HTTP and isolated storage do not prove Spotify’s binary SDK, Keychain entitlements, native picker presentation, call confirmation, or real App Remote playback. Those require a signed iPhone with Spotify installed and an authorized test account.
